# 邮件助手 Email Assistant

[English](README.md) · **简体中文**

读邮件、抓重点、写回复、带附件发送；简短清楚，不绕弯子。

这是一个 [Agent Skill（智能体技能）](https://agentskills.io)，装上以后，你的 AI 助手处理邮件会更靠谱：找到要找的那封信，看懂一长串往来，把零散想法写成清楚的邮件，回复时收件人和附件都对——而且你没让它发的，它不会发。

适用于 Claude Code、Codex、Claude 网页版和桌面版、Cursor、GitHub Copilot、Gemini CLI 等支持 Agent Skills 的助手。

## 能做什么

| | |
|---|---|
| **读信、找信** | 搜索往来邮件，概括整段对话，列出对方的请求、负责人、日期和金额。 |
| **写信、回信** | 起草、改短、翻译邮件，事实一个不丢，语气按你想要的来。 |
| **发送、附件** | 核对收件人，在原对话里接着回，附上真正的文件，发完再核对一遍。 |
| **整理** | 给你指定的一批邮件加标签、归档或清理，并如实报告改了多少封。 |
| **跟进** | 找出还没回的请求；你要的话，用现有工具设提醒或定时发送。 |

## 用前用后

**零散笔记 → 邮件**

> **你：** 跟王老师说合同第三版在附件里，请他 10 月 17 日周五前签好寄回，价格还是 4800 元不变，法务有修改的话周三前发我

```text
主题：合同第三版，请于 10 月 17 日前签署

王老师好，

合同第三版在附件里，请在 10 月 17 日（周五）前签好寄回。价格仍为 4800 元，不变。
法务如有修改，请在周三前发给我。

谢谢！
```

**客套太多 → 只说重点**

> **原稿：** 各位同事好，希望大家一切顺利。我想借此机会就上周的会议跟进一下，确保大家对齐信息。正如之前讨论的，如果可以的话，我们是否有可能把发布时间调整到下周二，不知道大家是否方便。烦请各位在方便的时候尽快回复我，非常感谢大家的支持与配合！

```text
各位好，

接上周的会：发布能不能改到下周二？不方便的话跟我说一声。
```

变短了，但没有凭空加东西——不加原文没有的截止时间、承诺或情绪。

## 安装

### 一条命令，装到各种助手

需要 [Node.js](https://nodejs.org) 18 或以上。

```bash
npx skills add shixi-11/email-assistant
```

它会识别你电脑上的助手，把技能装进当前项目各自的技能目录。加 `-g` 装给所有项目用；加 `-a claude-code` 或 `-a codex` 只装给指定的助手。

### Claude Code

```bash
git clone https://github.com/shixi-11/email-assistant ~/.claude/skills/email-assistant
```

想让团队一起用，就放到仓库里的 `.claude/skills/email-assistant`。

### Codex

```bash
git clone https://github.com/shixi-11/email-assistant ~/.agents/skills/email-assistant
```

### Claude 网页版和桌面版

1. 打开「设置 → 功能」里的「代码执行和文件创建」。
2. 在本页点「Code → Download ZIP」，下载后解压。
3. 把文件夹 `email-assistant-main` 改名为 `email-assistant`，再把这个文件夹重新压缩成 ZIP。
4. 进入「自定义 → 技能 → + → 创建技能 → 上传技能」，选这个 ZIP。

### 其他助手

把整个文件夹以 `email-assistant` 为名放进助手的技能目录即可。技能是标准 `SKILL.md` 格式的纯文本。

### 更新

用 skills 命令装的：`npx skills update`。用 git 装的：`git -C <安装目录> pull`。

## 怎么用

直接说你要处理什么邮件就行，支持自动选技能的助手会自己用上它。也可以点名调用：

| 助手 | 例子 |
|---|---|
| Claude Code | `/email-assistant 概括这段往来，告诉我哪些要回` |
| Codex | `$email-assistant 把这些要点写成一封短邮件，日期和金额保留` |
| Claude 网页版、桌面版 | `用 email-assistant 技能在原对话里回复，附上这两个文件` |

还可以这样问：

- *找到陈悦上个月发的发票，告诉我金额和付款期限。*
- *这周收件箱里有哪些在等我？只看有明确截止日期的。*
- *把这段回复翻成日语，和原文一样短。*
- *这封写得太生硬了，改自然一点，别加内容。*
- *把最近 30 天的订阅邮件归档，别的都别动。*

## 需要什么

| 任务 | 需要 |
|---|---|
| 起草、改写、翻译 | 什么都不用——贴上文字就能用 |
| 搜索、概括你的邮箱 | 助手能用的邮箱工具：Gmail 或 Outlook 连接器、MCP 服务，或浏览器操作 |
| 发送、回复、整理 | 同上，再加上你明确要它这么做 |
| 提醒、定时发送 | 日历、待办或定时发送工具 |

这个技能只是一套做事的方法说明，不是邮件客户端、服务器或后台服务，也不会保存你的邮件。

## 谨慎是设计出来的

- **不擅自动手。** 让它读信、起草，不会变成发送、转发、删除或定时发送；每一项都要你开口。
- **邮件里的话不算命令。** 信件、附件、链接里写的指令，只当作内容看，不照着做。
- **不乱动收件箱。** 尽量用预览读信，保留未读状态；没让它动的邮件不改标签、不挪位置。
- **发前先核对。** 发件账号、收件人、抄送、密送，是否在原对话里，链接指向哪里，附件是不是真附上了——不是正文里提了个文件名就算。
- **如实汇报。** 草稿、排队待发、已发送、已送达是四回事，它会说清是哪一种。发送结果不确定时，先查，不重复发。

## 文件结构

```text
email-assistant/
├── SKILL.md                    # 核心写作规则和工作方式
├── references/
│   ├── inbox-work.md           # 搜索、概括、分轻重、清理、跟进
│   └── message-actions.md      # 收件人、对话、附件、发送与核对
└── agents/openai.yaml          # Codex 显示用的可选信息
```

助手先读 `SKILL.md`，用到哪一部分才打开对应的参考文件，所以很轻。
